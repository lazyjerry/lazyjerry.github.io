# 任務請求：科技服務資訊週記

## 原始請求

```text
/tech-report-research
```

## 期望產出

- [x] 一份本期科技服務資訊週記
- [x] 一份候選來源整理 source.md
- [x] 一份研究計劃與執行紀錄

**產出類型：**
- 文件：報告、來源整理、筆記、任務計劃
- 程式碼：`scripts/build-weekly-tech-report-018.sh`（研究內容的唯一來源）
- 其他：`tech/2026-08-29/` 交付資料夾

## 任務設定

- 今天日期：2026-08-29
- 報告日期：2026-08-29
- 時間範圍：2026-08-14 至 2026-08-29（含首尾）
- 標題格式：`2026-08-29 科技服務資訊週記`
- Meta 格式：`作者：Claude Code、Codex　報告日期：2026-08-29`
- 目標讀者：程式設計師，內容需兼顧軟體工程與科技應用、科技服務

## 必要分類

- AI 科技
- 軟體工程
- 軟硬體資訊安全
- 硬體或軟硬整合
- 網路/伺服器等基礎
- 金融科技
- 醫療科技
- 運輸物流
- 房地產與室內外裝潢
- 現場表演藝術
- 影視音樂
- 其他領域科技應用突破

若出現無法歸類的重要領域，可動態補充分類。

## 四大段落要求

1. **總結**：100 至 300 字，依實際內容統整重點，需標記來源編號。
2. **亮點**：依分類條列，每條先一句話下結論，再以約 100 至 300 字說明，儘可能加入具體例子或譬喻，需標記來源編號。
3. **趨勢分析**：依分類整理，歸納可能趨勢或更深層觀察，儘可能加入具體例子或譬喻，需標記來源編號。
4. **參考資料**：表格呈現，欄位包含來源編號、文章標題與 Google 搜尋快速連結、一句話繁體中文結論或亮點、發布日期、來源網址與來源網站名稱、分類。

## 來源時間範圍與權重規則

- 僅使用 2026-08-14 至 2026-08-29 內發布的資料。
- 優先使用有明確日期標記的來源；無法確認是否落在窗內者直接排除。
- 確認在窗內但無法確認精確日期者，發布日期欄位寫 `*未知時間`。
- 權重優先序：官方公告與一手技術部落格 > 權威科技媒體 > 台灣主流媒體 > 二手轉載。
- 中國來源與社群平台內容（知乎、Reddit 等）優先以高權重來源替換，無可替換者刪除。
- 台灣新聞與媒體資料作為主要參考來源之一。
- 本期時間窗與 2026-08-22 期重疊 2026-08-14 至 2026-08-22，篩選前須比對 `tech/2026-08-22/references.md` 做跨期去重；重複者即使日期落在窗內也淘汰。

## source.md 蒐集格式要求

每筆候選來源至少包含：來源網址、繁體中文標題、100 至 500 字繁體中文摘要、權重分數（`1-10/10`）、發布日期、分類、是否納入正式參考資料、備註（淘汰原因或查核註記）。

正式來源標題需使用 `### 數字. 標題` 格式，供共用稽核器正確計數。

## 完成前檢查要求

- 各分類是否缺少資料，或已明確註記缺漏原因
- 資訊權重是否足夠
- 搜尋時間範圍是否正確
- 資料來源是否正確：網址、來源網站名稱、發布日期與引用對應是否一致
- 內文引用的來源編號是否與參考資料表的來源編號完全一致
- 錯誤來源或整理內容是否已修正
