# 多組代理平行蒐集的收斂規則

## 觸發時機

- 以多組研究代理依分類平行蒐集候選來源時
- 收斂代理回傳的候選檔、決定正式與淘汰名單時
- 建置 `source.md` 前檢查摘要字數與時間窗時

## 內容

### 分組與輸出格式

- 依分類拆成四組：AI＋軟體工程／資安＋基礎＋硬體／金融＋醫療＋運輸／房地產＋表演＋影視＋其他。稀疏分類（表演藝術、影視音樂、醫療）在提示裡明定補搜輪次下限（7 至 9 輪）。
- 每組寫成與 `source.md` 相同欄位的 markdown，另加「來源網站」與「程式設計師觀點」兩欄供撰稿，收斂時剔除。
- 提示裡要附前兩期 `references.md` 的已引用清單，並要求每筆正式建議都 curl 到 HTTP 200、日期取自原頁。

### 收斂工具

- `scripts/converge-weekly-tech-report-candidates.py <候選目錄> order.txt rejects.txt out_formal.md out_reject.md 窗起 窗迄`：依 `order.txt` 的網址順序編號正式條目、淘汰條目編字母、剔除撰稿欄位，並檢查摘要 100 至 500 字與時間窗。
- 主編補查或修正的條目寫成 `candidates-X.md`，同網址會覆蓋代理版本；單一欄位（精簡摘要、改中文標題）用 `overrides.tsv`。
- 代理列為正式但主編未採用的條目，必須在 `rejects.txt` 給淘汰原因，否則腳本報錯。

### 收斂時的固定檢查

- **逐筆讀備註**。代理常把第三方媒體的數字混進摘要，並在備註自己標出來；收斂時把這些句子從摘要刪掉，否則報告會把別家的事實掛在這個來源名下。
- **摘要字數**。代理摘要常寫到 500 至 700 字，每期約有一至兩成要精簡；精簡只刪不補，不能加入原頁沒有的內容。
- **同一 URL 出現在多組**。例如一則 MIT 研究同時被醫療組列為備援、其他領域組列為正式，由主編統一分類。
- **代理的跨組建議**。代理會把不屬於自己分類的高權重來源列在淘汰候選並註明「建議交由他組」（例如 Java 27、Akamai 算力合約）；收斂時要掃一遍淘汰候選的這類備註，否則會漏掉。
- **候選檔分段**。解析時 `## 淘汰候選` 標題行要單獨判斷，不能和前一筆 `###` 條目併在同一段，否則每組最後一筆正式建議會被歸到淘汰。

### 撰稿後的逐筆稽核

- 把正式來源的原頁抓回本機（`audit-weekly-tech-report-sources.sh`），再分四組稽核代理各 12 至 13 筆，只讀本機副本不上網，逐句對照參考資料表、`source.md` 摘要與 `report.md` 引用句，每條回報附原頁原文；主編回原頁 grep 一次才裁決。
- 代理摘要可信度高，問題多出在主編撰稿時的延伸措辭。固定檢查四類：**狀態與時態**（預告寫成已上市、單日實證寫成持續進行、「考慮」寫成已決定）、**原頁沒有的定性**（「周邊系統」「核心」「用了 10 年」「不需電池」這類報告自己加的概括）、**歸因**（通訊社綜合外電要寫出引述對象；原頁未歸給某機關的句子不能寫成該機關指出）、**語意精度**（workaround 與 mitigation、encouraged 與要求、validate 與校正、「至少 N」與確數）。
- 修正一律寫成斷言式字串替換腳本，對收斂輸出與報告正文片段套用後重建，不手改生成檔；補入的來源接在表末、不重排編號。
- 替換腳本若直接改寫持久的片段檔，**新字串不可包含舊字串**（例如在某句後面接一段話時，舊字串只寫那句）：每次重跑都會再插一次。舊字串要包含插入點後面的文字，重跑時才會因為找不到舊字串、找得到新字串而跳過。
- **「原頁沒有」的否定式主張也要稽核。** 蒐集代理常只讀正文，漏看新聞稿副標、頁尾模型卡這類位置，備註寫「原頁無金額／價格不在官方頁」，主編再據此寫進資料限制，結果方向相反地出錯（2026-10-10 期格芯副標的 20 億美元、Mistral 模型卡的 API 價格）。稽核簡報要明列：資料限制段每一句「只見於某報導、原頁未提供」都要回原頁全文 grep 確認。
- **稽核代理改用文字回報。** 子代理寫稽核報告檔會被 harness 擋下（訊息要求以文字回傳），蒐集代理寫候選檔則不受影響；稽核簡報直接要求在最後訊息回傳完整稽核內容，不要指定輸出檔。
- 以「新字串已存在」判定已套用時，若新字串剛好是舊字串的前綴或子字串（例如刪除句尾一句），首輪就會被誤判跳過；這類刪除改用單獨替換，或讓舊字串與新字串的差異落在兩端都看得到的位置。
- **第二輪查核開原始網址的價值在內文與補搜，不在元資料。** 2026-10-10 期重開 51 筆原頁，標題、日期、媒體名稱零差異、正文與第一輪本機副本零差異，但仍找出 10 處內文語意問題（模式名稱錯置、「常」與「多起」、結算雙方是誰），補搜也補進 6 筆明顯高於現有選材的事件。蒐集與第一輪稽核做得紮實時，第二輪可以把力氣放在逐句語意與跨分類補搜。
- **補搜代理的存檔檔名要帶可辨識的 slug，不要只編號。** 代理回報的序號與實際存檔對不上（gap-9 存的是另一頁），主編要靠 `<title>` 重新對應；簡報直接要求檔名用「序號-網域-slug」。
- **稽核前先替每筆 ref 產生稽核包。** 由收斂輸出與建好的 `report.md` 自動抽出：本機原頁路徑（從備註的存檔檔名解析）、`source.md` 條目、參考表列、報告中所有引用該 ref 的段落（含資料限制段）。稽核代理不必自己翻報告找句子，四組約 4 至 6 分鐘回齊，2026-10-17 期找出 94 處修正。
- **否定式主張的錯誤也會出現在蒐集代理的備註。** 2026-10-17 期代理備註寫「該站無 datePublished」「iThome 說的那句原頁沒有」，兩者原頁都有；正文雖未沿用，`source.md` 仍會留下錯誤紀錄。稽核範圍要包含備註。
- **稽核修正後重量摘要字數。** 補上歸因或範圍說明常讓摘要超過 500 字（本期 3 筆），驗證腳本會擋下；精簡時只刪不補，刪重複的年份、縮寫與次要背景，不刪剛補上的修正。
- **稽核包必須含資料限制段。** 資料限制段排在參考資料表之後，稽核包腳本若在 `references` 錨點截斷，這段逐筆引用的句子就全部消失，四組稽核代理會一致回報缺段；抽正文時要另接 `limitations` 至 `disclaimer` 之間的內容。
- **`grep 核對` 清單只用「、」分隔。** 用全形逗號會被 `validate-weekly-tech-report-source-terms.sh` 當成一個詞整串比對；原頁被標籤切開的片語（`nearly $10 billion`、`2,000 gamma-ray bursts`）要拆成兩個詞，比對才會過。
- **第三輪仍有收穫，重點在歸因與補搜。** 2026-10-24 期前兩輪後第三輪仍修 50 處，多數是記者敘述或他人引言寫成受訪者或機關的話、原頁沒有的「約」字與定性；補搜補進 4 筆高權重官方來源（NIST／NSA／CISA 應變指引、TorchTPU、OCC 穩定幣最終規則、Merck／Moderna 第三期結果）。開發者大會盤點不能只看 OpenAI、Google、Microsoft，PyTorch Conference 這類基金會年會也算。
- **多支斷言式腳本串接時，後輪會改寫前輪的新字串。** 前輪腳本以「新字串已在」判斷已套用，後輪一改那句，前輪重跑就報錯。前輪補一張「後輪改寫後的句子」對照表（命中也算已套用），追加句的判斷只看附加的那一句不看前文；後輪的 `replace()` 要先檢查新字串是否已在再數舊字串，否則新字串包含舊字串的追加型替換每次重跑都會再追加一次。三支腳本任一順序重跑後比對 build script 的 hash 不變才算相容。
- **前輪的追加型替換被後輪改字後，重跑不會報錯而是再追加一次。** 2026-10-31 期第一輪把「，多數既有 App 可直接使用」接在「macOS 會自動把觸控轉成點擊」之後，第三輪改成「許多」，第一輪重跑找不到新字串、舊錨點仍在，就再接一次。只看重跑有沒有失敗抓不到；要乾跑前輪腳本，把實際替換的那行改成印出標籤，列出所有「會改動」的標籤，一併補進 `SUPERSEDED` 對照表。後輪 `replace()` 另加並存檢查：新字串已在、新字串不含舊字串而舊字串也還在時報錯，source 與 report 前後文相同的句子靠這道檢查才分得出來。

### AI 組的固定盤點來源

- 除了 GitHub Changelog 與各語言部落格，AI 開發工具自己的 Release／CHANGELOG 也要盤點（例如 `github.com/anthropics/claude-code/releases`、npm registry 的發布時間）；2026-10-03 期因此漏收 Claude Mods 正式推出。
- 窗內有大型開發者大會（OpenAI DevDay、Google I/O、Microsoft Build 等）時，要另收一則開發者端彙整，不能只收消費端產品；openai.com 擋抓取時可用 InfoQ 這類開發者媒體的彙整。社群論壇的彙整貼文先確認作者是不是官方。
